# YC-7ZIP

网页端的压缩与解压工具，**直接在 NAS 上读写文件**，不需要先把文件上传到浏览器里再打包。

支持 `7z` / `ZIP` / `RAR` / `TAR` / `GZ` / `BZ2` / `XZ` / `ZSTD` / `ISO` / `CAB` / `WIM` / `CPIO`
等格式，并且支持**分卷压缩与分卷解压**。

> 为什么值得单独做一个：飞牛 fnOS 自带的压缩功能**没有分卷选项**
> （zh-CN 语言包里「分卷」出现 0 次），而分卷恰恰是把大文件投递到网盘、
> 微信、FAT32 移动盘时最常需要的能力。

---

## 它长什么样

在飞牛文件管理器里右键一个压缩包 →「打开方式」→ YC-7ZIP，会弹出一个浮动窗口，
界面里已经把这个文件选好、把格式和分卷情况列清楚，选一下输出目录就可以解压：

```
┌ 文件管理器 ─────────────────────────────┐
│  📦 movie.7z.002          [右键]         │
│      └ 打开方式 ▸ 通过 YC-7ZIP 打开      │
└──────────────┬──────────────────────────┘
               ▼
   ┌ YC-7ZIP ────────────────────────────────┐
   │  分卷  这是一个分卷压缩包 · 共 6 卷       │
   │        movie.7z.001 … movie.7z.006      │
   │  压缩包内容  blob.bin            2.9 MB  │
   │  输出位置  /vol5/1000/空间4        [选择] │
   │                        [ 开始解压 ]      │
   └─────────────────────────────────────────┘
```

选中 `.002` 也能解压——程序自己会找到第一卷并把其余分卷收集起来。

## 图览模式

文件浏览器有「列表」与「图览」两种视图，看的是同一个目录，多选状态也一起带着走。
图览里每个文件就是一块缩略图：

图片的缩略图由**服务端**生成，并**按 EXIF 方向摆正**。这两点都不是顺手加的：
把一个放了几百张手机照片的目录原图丢给浏览器去缩，NAS 和手机都会被拖住；
而手机照片在文件里往往是「横着」存的，靠一个方向标记来纠正，
不读这个标记的相册打开就是一片躺倒的照片。服务端只解码 Go 标准库认得的格式
（JPEG / PNG / GIF），方向标记取自 JPEG 的 EXIF；缩略图带 ETag
（把尺寸、修改时间、文件大小都算进去）与一小时缓存，来回翻不会反复解码。

WebP、AVIF、HEIC、BMP、TIFF、SVG 这类服务端解不了的格式，会重定向到原文件
交给浏览器自己解码——浏览器的解码器比任何值得为它引入的 Go 依赖都全；
既然交给浏览器，方向纠正也归浏览器管。

视频不预先生成首帧图片，而是让浏览器用 `preload="metadata"` 自己画第一帧。
为了避免一次列目录就并发拉几十个视频头，`<video>` 元素只在磁贴滚到视口附近时
才挂上去（IntersectionObserver，提前 200 px 预取）。

面板右上角还有**类型筛选**：全部 / 图片 / 视频 / 压缩包 / 文档。筛选只作用于文件，
目录始终保留——否则筛一下就没法往下点进子目录了。

**大图查看**：点磁贴角上的按钮或双击打开，图片看原图，视频可以直接播放，
脚注显示大小与完整路径。这里最有用的一点是它**能直接选中文件**——
看图确认「就是这张」之后不必关掉再回头找，当场选中即可。

> 图片有上限保护：源图超过 6000 万像素就不生成缩略图（压缩包里塞一张能把人撑爆的图
> 是常见套路），界面退回一个图标而不是破图；文件超过 96 MB 则干脆不读来做缩略图，
> 直接交给浏览器。另外 `/api/raw` 只服务图片与视频扩展名——挑文件的接口本来就能读
> 所有允许的路径，这个口子不收紧的话，它就是一个通用的任意文件下载接口。

## 设置面板

顶栏右上的齿轮打开设置，里面三块：版本与更新、壁纸、更新日志。

### 检查更新与在线更新

「检查更新」会去 GitHub Releases 里找出适用于当前发布通道的最新版本，
显示版本号、发布时间与发布说明，并列出**当前版本**、**当前通道**与**部署形态**
（容器 / 飞牛应用 / 裸二进制）——能不能就地更新完全取决于后者。

版本号是 `zip<YYMM>.<NNN>`，位数固定且补零，所以字符串比较就是版本比较，
不需要解析，也就不会在解析上出错。

**裸二进制部署可以就地更新**，顺序刻意设计成「越晚破坏越好」：

1. 下载当前架构的发布包（上限 256 MB）；
2. 发布里带 `SHA256SUMS.txt` 就一定校验 SHA256——宁可装不上，
   也不能装进一个被改过的东西；
3. 把新二进制解到临时文件，**以 `-version` 跑一次**：能跑、并且报出的版本
   与包名和预期一致才继续。这一步挡掉的是「文件下坏了」和「架构不对」；
   报出的版本不高于当前版本直接拒绝，不降级；
4. 备份当前程序为 `yc7zip.bak`，然后在同一目录内 `rename` 原子替换，并补上执行位。

任何一步失败都不会动到正在运行的程序。替换成功后进程退出（等 1.2 秒把响应发完），
下一次启动就是新版本。

> **容器与飞牛应用部署会被明确拒绝**，并说明正确的升级路径：容器里替换文件会在重启后
> 回到镜像里的版本，请更新镜像标签后 `docker compose pull && docker compose up -d`；
> fpk 的升级归应用中心，装新版本的 `.fpk` 即可。形态对但程序所在目录不可写，同样会被拒绝，
> 面板会直接说清楚是哪个目录。

> 发布包里的 `start.sh` 是用 `setsid` 把进程放到后台，本身不做守护。所以裸二进制下
> 更新完成后需要自己再跑一次 `./start.sh`，或者干脆把这个进程挂在 systemd 之类
> 会把它重新拉起来的管理器下面。

GitHub 在部分网络下直连不到，所以检查更新用的出站代理可以配：
`-proxy http://192.168.1.8:7890`，或环境变量 `YC7ZIP_PROXY`。
面板打开时先显示上一次的结果（不触网），点「检查更新」才真的去问各条渠道。
仓库地址默认指向本项目，fork 之后用 `-repo` / `YC7ZIP_REPO` 改掉（参数表见下文）。

**检查更新有多条渠道**，默认第一条是自建源（发布目录里的 `update.json`），
第二条是 GitHub Releases；设置面板里可以只查其中一条。几条渠道会**分别报结果**，
所以"自建源还没同步"和"GitHub 连不上"是能分辨的，而不是笼统的一句"检查失败"。
换渠道或调顺序用 `-update-sources`（可重复，也可用 `YC7ZIP_UPDATE_SOURCES`
逗号分隔）：每项是一个自建源目录地址，或 `github[:owner/repo]`。

在线更新下载的包会先过 SHA256——自建源用 `update.json` 里的摘要，GitHub 用
`SHA256SUMS.txt`；**拿不到校验值就直接拒绝安装**，因为这一步换的是本机可执行文件。
自建源应当用 https：明文 http 下摘要与包可能被一起改写，校验就只剩防传输损坏的作用
（启动时会对 http 源告警）。

**本地更新**是给没有外网的 NAS 准备的：上传一个发布包（`.tar.gz`）或一个裸二进制即可。
这条路径没有远端的校验文件，所以能校验的只有「它确实是一个能跑起来的新版本」——
同样会跑 `-version`，同样拒绝降级。

### 自定义壁纸

上传一张图片当壁纸。暗化（0–90%，默认 45%）是保证文字可读的关键；
模糊（0–40 px）、铺满方式（铺满裁切 / 完整显示 / 平铺）与**面板透明**
（0–90%，默认 8%）按喜好调——面板调得越透，壁纸越能透出来，
而这一步带来的可读性代价正好由「暗化」补回来。

壁纸铺在一个固定在最底层的层上，内容面板照旧是实色的：照片只在留白处透出来，
文字永远落在实色面板上，不会出现「浅色照片上白字看不清」。暗化的颜色按当前主题算，
浅色主题会把照片往亮里压。

设置存在服务端的 `-data` 目录下（`ui/settings.json` 与 `ui/wallpaper.<ext>`），
不是浏览器本地存储。飞牛里这个应用是嵌在 iframe 里的，换台设备、清一次站点数据
就全丢了；存服务端则一次设置处处生效。所以 `-data` 指向哪里值得想一下：
默认的系统临时目录在重启后会被清掉，壁纸与设置也跟着没了。

> 壁纸上限 24 MB，类型按**文件内容**判断而不看扩展名——从 NAS 上挑的图可能叫 `.jpeg`
> 而实际是 PNG，类型判错浏览器就不会渲染，白白让人以为没生效。
> 支持 JPEG / PNG / GIF / WebP / AVIF。

### 更新日志

设置面板底部直接显示更新日志。`CHANGELOG.md` 在仓库根目录，构建时 `go:embed` 进二进制，
由 `/api/changelog` 提供给界面——NAS 常常待在内网里，而「这个版本改了什么」
恰恰是升级前最想确认的事，所以它不依赖网络。

同一份文件在构建时还会被渲染进静态下载页，下载页与应用里看到的是同一份内容。

## 三种部署方式

### 1. Docker（通用）

取一份 `docker-compose.yml`（Release 或下载页），**改两行**——要操作的目录
（`- /vol1/1000:/share`）与版本（`image:` 那行）——然后：

```bash
docker compose up -d          # 打开 http://<NAS 地址>:8090
```

升级就是把 `image` 那行的版本改掉，再 `docker compose pull && docker compose up -d`。

不想用 compose，`docker run` 一行也行：

```bash
docker run -d --name yc-7zip -p 8090:8080 \
  -v /vol1:/vol1 -v yc7zip-data:/data \
  ycyingchen/yc-7zip:latest \
  -addr :8080 -data /data -allow-root /vol1
```

多架构镜像：`linux/amd64`、`linux/arm64`。

### 2. 飞牛 fnOS 应用包（fpk）

**不需要 Docker。** 包里自带 `yc7zip` 与官方 `7-Zip`（x86_64 与 arm64 各一份，
安装时按 `uname -m` 现选），由应用包自己拉起进程，数据落在应用的 `TRIM_PKGVAR`。

直接下现成的包：Release 里的 `yc-7zip-<版本>.fpk`，或下载页上的 `yc7zip.fpk`。
然后到「应用中心 → 手动安装」选中它。

自己从源码打包（在 NAS 上，已预装 `fnpack`）：

```bash
git clone https://github.com/YCyingchen/YC-7ZIP.git
cd YC-7ZIP
# fpk 源码里不含二进制，先按架构补上（二进制在 Release 的 linux-<arch> 包里）
install -Dm755 <解开的 yc7zip> deploy/fpk/app/bin/amd64/yc7zip
install -Dm755 <解开的 7zz>    deploy/fpk/app/bin/amd64/7zz
fnpack build -d deploy/fpk               # 生成 deploy/fpk/yc7zip.fpk
```

装好后会有两个入口：

- 桌面/应用列表里的 **YC-7ZIP** 图标；
- 文件管理器里对压缩包右键 →「打开方式」→ **YC-7ZIP 压缩解压**。

> **它能读写的范围由一份目录清单决定。** 安装时会问（默认 `/vol1/1000`），装好之后
> 还能在「应用中心 → YC-7ZIP → 应用设置」里改，改完应用会自动重启让新值生效。
> 这份清单就是它的安全边界：不在清单里的路径一律 403，**父目录也不隐含**——
> 列了 `/vol5/1000/空间4` 不等于放开了 `/vol5/1000`。
> 应用包自身以 root 运行（用途就是读写 NAS 上的压缩包，同类的 Lucky 也是这样），
> 但真正碰得到的只有清单里那几个目录。

> 端口只绑在 `127.0.0.1`：飞牛的应用网关是通过 unix socket 进来的，
> 不需要把端口暴露到局域网。想直接从别的机器访问端口，给 `cmd/main` 里的
> `-addr` 去掉 `127.0.0.1` 前缀，并务必同时打开 `YC7ZIP_AUTH`。

> 右键菜单的实现方式是飞牛官方支持的**文件类型关联**（`app/ui/config` 的
> `fileTypes`）。飞牛不支持往右键菜单里塞任意菜单项，所以入口在「打开方式」子菜单里。

### 3. 裸二进制

从 [Releases](https://github.com/YCyingchen/YC-7ZIP/releases) 下载对应架构的压缩包：

```bash
tar -xzf yc-7zip-<版本>-linux-amd64.tar.gz
cd yc-7zip-<版本>-linux-amd64
./start.sh 8090                     # 默认端口 8090
./stop.sh
```

包内自带官方 `7zz`，不需要另外装 7-Zip。

## 命令行参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-addr` | `:8080` | HTTP 监听地址；留空则只监听 `-socket` |
| `-socket` | 空 | 额外监听一个 unix socket，例如 `/trim/app.sock` |
| `-base-path` | 空 | URL 前缀，例如 `/app/yc7zip` |
| `-data` | 系统临时目录 | 任务工作区；下载模式的结果与界面设置（壁纸）都放这里 |
| `-allow-root` | 无 | 允许读写的目录，**可重复**。不指定就不能直接操作 NAS 文件 |
| `-auth` | 空 | HTTP Basic 认证，格式 `user:password` |
| `-max-upload` | `4G` | 单任务上传上限，`0` 表示不限 |
| `-job-ttl` | `2h` | 结果保留时长 |
| `-repo` | 本项目仓库 | 项目仓库地址；fork 之后改这里，界面上的反馈入口与检查更新都用它 |
| `-update-sources` | 自建源 + GitHub | 检查更新的渠道与顺序，**可重复**：自建源目录地址，或 `github[:owner/repo]` |
| `-proxy` | 空 | 检查更新用的出站代理，例如 `http://192.168.1.8:7890` |
| `-quiet` | 关 | 只输出错误日志 |
| `-version` | 关 | 打印版本号后退出（在线更新正是用它问新程序是哪个版本） |

也可以用环境变量：`YC7ZIP_ADDR` / `YC7ZIP_SOCKET` / `YC7ZIP_BASE_PATH` / `YC7ZIP_DATA` /
`YC7ZIP_AUTH` / `YC7ZIP_MAX_UPLOAD` / `YC7ZIP_ALLOW_ROOTS`（逗号分隔）/
`YC7ZIP_REPO` / `YC7ZIP_UPDATE_SOURCES`（逗号分隔）/ `YC7ZIP_PROXY`。

`YC7ZIP_7Z` 可以指定 7-Zip 可执行文件的位置；不设的话会依次在自身目录、
`PATH` 和常见安装位置里找。

## 安全说明

这个工具会按你的配置读写 NAS 上的文件，请留意：

- **`-allow-root` 是唯一的边界。** 只有列在这里的目录能被浏览和写入，
  其它路径一律拒绝（返回 403），**而且父目录不隐含**——列了 `/vol5/1000/空间4`
  不等于放开 `/vol5/1000`。三种交付方式各自决定这份清单：

  | | 清单由谁定 | 默认 |
  | --- | --- | --- |
  | 飞牛应用包 `.fpk` | 安装向导里填，装好后还能在「应用中心 → 应用设置」里改 | `/vol1/1000`，留空则 `/vol1` |
  | Docker | `compose` 里的 `YC7ZIP_ALLOW_ROOTS`（写**容器内**路径） | `/share`（＝挂进来的那个卷） |
  | 裸二进制 | 命令行 `-allow-root`，可重复 | 不传就不开该功能，只能上传文件 |

  前两种都是给别人的机器准备的**保守默认**；自己用图方便，就在安装向导或
  compose 里写成 `/vol1,/vol2,…` 甚至 `/`。
- **容器能看到的路径 = compose 里挂进去的路径。** 应用的 `/` 是容器自己的根，
  不是 NAS 的根；数据在哪些卷上，就把哪些卷挂进来。
- **容器与应用包都以 root 运行**，这是为了能写入属于 NAS 用户、权限受限的目录。
  应用包与容器都只把端口绑在 `127.0.0.1`，访问必须经过飞牛的登录态；
  如果放开端口，请同时打开 `-auth`。
- 解压时会先校验压缩包内的路径，遇到 `..`、绝对路径等越界条目会直接拒绝，
  不会依赖 7-Zip 自己的净化行为。
- 上传与下载都限制在任务工作区内，`?file=` 参数经过两次路径校验
  （词法 + 真实路径），防止越界读取。

## 版本号规则

```
zip<年份后两位><月份>.<当月修订号>

zip2609.001
│  │  │   └── 该月第 1 次修改
│  │  └────── 09 月
│  └───────── 2026 年
└──────────── 项目前缀
```

`VERSION` 文件是唯一来源，Docker 标签与二进制内的 `main.version` 都由它推导。

**飞牛 fpk 是唯一的例外**：`fnpack` 打包含有版本号的 manifest 时只接受 semver
（`x.y.z[-r]`），`zip2609.001` 会被直接拒绝。所以 manifest 里写的是换算值
`26.9.1`（年.月.修订），由脚本生成、CI 校验：

```bash
python3 tools/version.py fpk             # zip2609.001 -> 26.9.1
python3 tools/version.py sync-manifest   # 把换算值写进 deploy/fpk/manifest
```

## 发布通道

通道记在仓库根目录的 `CHANNEL` 文件里，只有 `test` 与 `stable` 两个值：

```bash
python3 tools/version.py channel               # 查看当前通道
python3 tools/version.py channel --set stable  # 切换
```

通道不改变版本号，它决定这个构建被当成什么：

- **镜像标签**：`test` 推 `:test`，`stable` 推 `:latest`；版本标签（`zip2609.002` 这种）
  **总是**打，并且不可变——想回滚到某个具体版本，标签永远在。
- **GitHub Release**：`test` 发成预发布，`stable` 才是正常的 Release。
- **检查更新**：`test` 通道连预发布一起看，`stable` 通道只看正式版。

镜像标签与 Release 是否预发布是**构建时**按 `CHANNEL` 决定的，都是生效的；应用内的通道值
则是**编译期**注入的（`main.channel`），而发布脚本目前只注入版本号，所以按现有脚本构建出来的
二进制一律按 `stable` 处理——即使 `CHANNEL` 写成 `test`，应用内也不会把预发布当成更新。

## 开发

```bash
python3 tools/dev.py check          # gofmt + vet + 版本号校验
python3 tools/dev.py linux          # 交叉编译 linux/amd64 与 arm64
python3 tools/dev.py dist           # 产出发布件（二进制 + 7-Zip + tar.gz）
python3 tools/dev.py nas-test       # 推到 NAS 并在 NAS 上跑测试
python3 tools/dev.py nas-app        # 在 NAS 上构建镜像、推仓库、打 fpk、重装
python3 tools/dev.py nas-download   # 把下载页与产物放到 NAS 的下载目录
python3 tools/dev.py ui             # 真实浏览器验收
python3 tools/dev.py publish        # 一条命令走完整条发布链路
```

`publish` 是「每次改完都要发一次」这条要求的固化：本地检查 → 提交 → 推 GitHub →
打标签触发 Release → 在 NAS 上构建镜像、推 Docker Hub、打 fpk、重装 → 刷新下载页。
一步都不用手工记，也不会漏掉某一处。

配套的构建、部署与验收脚本同样是 Python（浏览器验收用 Node 跑 Playwright 脚本，见下）：

| 脚本 | 用途 |
| --- | --- |
| `tools/dev.py` | 构建、部署与验收入口，上面那些子命令都在这里 |
| `tools/version.py` | 版本号与发布通道的唯一来源：`show` / `fpk` / `check` / `bump` / `channel` / `sync-manifest` |
| `tools/changelog.py` | 把 `CHANGELOG.md` 渲染成下载页用的 HTML |
| `tools/e2e.py` | 对着已部署的服务跑 HTTP 端到端 |
| `tools/nas.py` / `tools/portforward.py` | NAS 的 SSH/SFTP 连接，以及与只监听 loopback 的服务对接的端口转发 |

构建工具一律用 Python 而不是 PowerShell / bash：这一路上引号和转义踩了太多次坑
（here-string 把 `$ROOT` 展开成空、`Set-Content` 按 ANSI 回写把中文搅乱、
`printf '%d' 09` 把月份当成八进制算成 0）。Python 里这些都是显式的。

界面是手写的，**零运行时依赖**：没有框架、没有 CDN、没有图标库、没有 web 字体，
图标全是内联 SVG，字体用系统字体栈；整个前端就是 `index.html` 加上 `assets/app.js`
与 `assets/style.css` 两个文件，Go 侧的 `go.mod` 同样没有第三方依赖。这不只是洁癖：
这个应用很可能跑在不联网的 NAS 上，而「资源来自 CDN 却加载不出来」是最难查的一类故障。

目录结构：

```
main.go                  入口、参数解析、监听方式（TCP 与 unix socket）
embed.go                 前端资源与 CHANGELOG 内嵌
index.html assets/       前端（单页，零依赖，中英双语，列表与图览双视图）
VERSION                  版本号（唯一来源）
CHANNEL                  发布通道（test / stable）
CHANGELOG.md             更新日志（嵌进二进制，同时渲染进下载页）
internal/engine/         7-Zip 封装：列表 / 解压 / 压缩 / 分卷识别
internal/job/            任务工作区与生命周期
internal/server/         HTTP API、NAS 文件浏览、服务端路径读写、缩略图、在线更新、界面设置
deploy/fpk/              飞牛应用包源码
deploy/download-page/    下载页
tools/                   构建、部署与验收脚本（Python，浏览器验收另有 Node 脚本）
```

### 验收脚本

项目自带三层验收，全部针对真实运行的服务：

```bash
# 1. Go 单元测试与集成测试（需要 7-Zip）
export YC7ZIP_7Z=/opt/7z/7zz
go test ./... -v

# 2. HTTP 端到端（对着已部署的服务跑）
python3 tools/e2e.py http://192.168.1.9:8090

# 3. 真实浏览器验收（Playwright）
export MIMO_NODE=/path/to/node.exe          # dev.py 用它启动下面的脚本
export PW_MODULE=/path/to/node_modules/playwright
python3 tools/dev.py ui
```

浏览器验收覆盖：浏览 NAS 文件 → 多选 → 分卷压缩写回 NAS → 选中**中间某一卷**解压 →
校验落盘内容 → 语言/主题切换 → 移动端无横向溢出 → 被 `?path=` 唤起时自动选中；
图览那条链也在里面：缩略图全部加载成功 → 带 EXIF 旋转的竖拍照片被摆正 → 类型筛选 →
点缩略图即选中 → 在大图里选中 → Esc 关闭。

设置面板的验收单独一份（它会在服务上真正设置并清除一次壁纸）：

```bash
export PW_MODULE=/path/to/node_modules/playwright
node tools/settings-test.cjs http://192.168.1.9:8092
```

它检查「检查更新」返回的是可读结果而不是异常、壁纸注入到页面（`body.has-wallpaper`）、
暗化与模糊滑块确实改变了渲染值、清除后壁纸层移除，以及全程没有 JS 异常与失败请求。

## 反馈与排错

界面上出错时不会只弹一个会消失的提示：**完整报错会留在页面上**，并附带
环境信息（版本号、7-Zip 路径与版本、来源路径、输出目录、分卷信息）。

- 顶栏右上角的 GitHub 图标 → 项目仓库；
- 报错面板里的「复制报错信息」→ 一键复制全部内容；
- 报错面板里的「在 GitHub 提交 Issue」→ **自动把报错与环境信息预填进 Issue**，
  你只需要补一句"我做了什么"。

仓库地址默认指向 <https://github.com/YCyingchen/YC-7ZIP>，
fork 之后可以用 `-repo https://github.com/你/你的仓库` 或 `YC7ZIP_REPO` 改掉。

## 已知限制

- **RAR 只能解压。** RAR 的压缩算法未开放授权，任何第三方软件都无法生成 `.rar`。
- 飞牛的文件类型关联只按**扩展名**匹配文件，所以右键压缩只对文件生效；
  压缩整个文件夹请从应用图标进入。
- 飞牛原生压缩/解压的菜单项无法被第三方替换，只能作为「打开方式」的一个候选，
  可以在「管理默认打开方式」里把 YC-7ZIP 设为某个扩展名的默认。
